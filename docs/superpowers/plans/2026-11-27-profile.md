# Profile Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Profile page for registered users with stats (record, Forces, Generals, form, streaks), game history and account settings (rename, change password).

**Architecture:** When a game finishes, `closeGame` stores one `game_seat_results` row per human seat from the existing `finalSeatViews` snapshot. A pure `computeProfile` function turns a user's rows into the response, so memory and Postgres share one implementation of the number rules. Old games are filled in by an idempotent backfill that replays them.

**Tech Stack:** TypeScript, Fastify, Kysely and Postgres, Typebox schemas in `projects/protocol`, Angular standalone components with signals, Jest.

**Spec:** `docs/superpowers/specs/2026-11-27-profile-design.md`

**Plan-level call (deviates from the spec's wording, allowed by "Left to the builder"):** The repository returns a user's raw rows and `computeProfile` aggregates them in TypeScript, instead of a SQL `profileStats` query. One user has at most hundreds of rows, and the rules then exist once.

## Global Constraints

- **Layering:** The engine gains nothing. Stats code lives in `projects/server/src/profile/`. Components render server numbers and compute none.
- **Counted games:** Only status `finished`. Aborted, broken and outdated never count.
- **Win:** Seat id in `result.winningSeatIds`. **Loss:** in `result.losingSeatIds`. Neither: no outcome (`won` is null), counts as a game but not as a win or a loss.
- **Win rate:** Wins divided by wins plus losses, or null.
- **Force:** `ambitionist` when allegiance is `ambitionist`. Otherwise the printed Kingdom (Wei, Shu, Wu, Qun). Hidden Kingdom with no allegiance: no Force, left out of the table.
- **General plays:** Main and deputy each count once. `null` Generals are skipped. A General's wins are the wins of seats that played it in either slot.
- **Form:** Last 10 games by `finishedAt`, newest first. **Streaks:** consecutive wins; a loss or no-outcome game ends one.
- **`topGenerals`:** At most 10, ordered by games, then wins, then General id.
- **Modes:** `all`, `solo` (room visibility `solo`), `online` (room visibility `open`).
- **Routes:** Registered users only. `PATCH /api/me/profile` uses `normalizeDisplayName` (error `invalid_name`). `POST /api/me/password` errors `invalid_credentials` and `weak_password` (sign-up rule), keeps the current session and revokes the others.
- **Rename:** Applies to rooms joined afterwards. Past games keep their `games.seats` names.
- **UI text:** Title Case for labels, sentence case for sentences (see `CLAUDE.md`). English and Vietnamese, Vietnamese as draft.
- **Docs:** Capitalize every sentence, list item and table cell. Bullets over long paragraphs.
- **Local screens:** Do not modify Setup or Game.
- **Checks:** `npm test`, `npm run test:db` (Postgres on 5433) and `npm run verify` must pass before the last commit.

## Review Focus

- **User with no games:** `winRate` null, empty lists, zero streaks, no crash. Pinned in Task 3.
- **Seat whose Generals were never revealed:** Left out of Generals and Forces, still counted in totals. Pinned in Task 3.
- **Game with no outcome:** Counts in `games` and `noOutcome`, breaks a streak. Pinned in Task 3.
- **Guest-held seat:** Row written, never shown to anyone, removed when the guest is deleted. Pinned in Task 2.
- **Changing the password with a wrong current password or a weak new one:** Refused, nothing revoked. Pinned in Task 5.
- **Backfill run twice or hitting a game that cannot replay:** No duplicate rows, and the failure is logged without stopping the rest. Pinned in Task 4.
