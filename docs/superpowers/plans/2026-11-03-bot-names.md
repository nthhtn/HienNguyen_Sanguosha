# Bot Names Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every bot, offline and online, gets a random Three Kingdoms figure's name (not a General in any deck), shown in each viewer's language, instead of "Seat N" / "Bot N".

**Architecture:** A flat pool of 32 name ids lives in a content data file with English names and a Vietnamese locale file. A bot carries a dedicated optional `botNameId` next to its `name` (which keeps an English fallback) through engine `Player`, protocol, server records and the database. Clients resolve the id per viewer in `seatName` / `playerLabel`. A person may use a bot's name, so the online name checks compare people only.

**Tech Stack:** TypeScript, Angular signals, Node server, Postgres (Kysely migrations) with an in-memory repository twin, Jest (`npm test`, `npm run test:db` needs `npm run db:up`).

**Spec:** `docs/superpowers/specs/2026-11-03-bot-names-design.md`

## Global Constraints

- The pool is exactly the 32 ids in Task 1, flat: no force field, nothing in code or UI groups or colours by force.
- No name in the pool is a General in the Kingdom Wars or Identity deck; a test asserts it.
- Ids are kebab-case and never shown. Names are proper nouns, capitalised word by word in both languages.
- Vietnamese names are drafts: they go in the Vietnamese locale file, count as draft in `npm run i18n:status`, and a missing Vietnamese entry falls back to English.
- Old saved games, rooms and replays keep their "Bot N" / "Seat N" names as stored; no data migration of names. Existing seeds, simulations and replays stay byte-identical (the draw never consumes the game's RNG).
- Engine and content stay framework-free; the draw takes its randomness as a parameter.
- Server and engine types change only by adding optional `botNameId`.
- UI text rules from `CLAUDE.md` apply. Work on `feat/bot-names`; never merge or push to `main`. Finish with `npm run verify`, `npm test` and `npm run test:db`.

## Review Focus

- A person joins or creates a room using a bot's name in English or Vietnamese: allowed, no `name_taken` (Task 3, Task 4).
- A bot with no `botNameId`, or an id no longer in the pool, shows its stored `name` (Task 1, Task 5).
- A viewer switching language sees the same bot renamed, with no reload (Task 5).
- A person whose display name equals a pool id ("zhou-cang") is never resolved as a bot (Task 5).
- The same offline seed gives the same bot names, and drawing names leaves the game's state and RNG unchanged (Task 6).
