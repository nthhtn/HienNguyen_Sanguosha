# Art Sets Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a player switch the portraits shown for Generals between art sets, globally and per General, with missing art falling back to `classic`.

**Architecture:** The asset pipeline learns sets (a folder level under `generals/skins`, a hand-kept registry and a generated coverage index). The content layer resolves URLs through a pure fallback chain that takes a choice object. A root-provided app service holds the player's choice and every portrait call site reads it.

**Tech Stack:** Python 3.9 `unittest` (`scripts/assetlib`), TypeScript, Jest (`content` and `app` projects), Angular standalone components with signals and `MatDialog`.

**Spec:** `docs/superpowers/specs/2026-11-25-art-sets-design.md` (read it first; this plan records only the decisions the spec leaves open).

## Global Constraints

- **Branch.** Work on a new branch from `main` (suggested name `feat/art-sets`). Never push or merge.
- **Commits.** Every commit message ends with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- **Untouched layers.** The engine, the server and `protocol` do not change. Art sets are presentation state.
- **Vocabulary.** The new concept is an "art set". "Skin" stays the single portrait image, and "card art" stays the crawled card scans, which are not part of an art set.
- **Default set.** The id is `classic`. It is always present and always complete.
- **Fallback chain.** A General's override set, then the global set, then `classic`, then (portraits only) the existing card-art and placeholder fallbacks. A set counts only if it has art for that General.
- **Assets.** An art set holds portraits and face crops only. Death voices, the face-down card (`generals/special/hidden`) and the placeholder stay shared by every set.
- **Pipeline.** Masters are in `projects/content/assets-src/` and `assets/` is generated. `assets:check` stays standard-library-only and is the one guard that `assets/` is current. The `classic` move is byte-identical.
- **Keys.** `skins.json` stays set-less and keyed by base General id (`"cao-cao": "wei/caocao"`). Overrides and the index are keyed by base General id (`baseGeneralId`).
- **Storage.** `localStorage` keys are `art-set` and `art-set-overrides`. Every read and write is wrapped in try and catch.
- **Picker.** The toolbar entry (and its phone drawer twin) is shown only when more than one set ships, on every screen including the Rules Wiki.
- **UI text.** English labels are Title Case, hints and status lines are sentence case. Vietnamese is sentence case everywhere and starts as a draft that `npm run i18n:status` reports.
- **Python.** Local Python is 3.9, so no `X | Y` unions and no `match`.

## Review Focus

- **Stale stored override.** An override whose set no longer covers that General (or no longer exists) is ignored and the General shows the global set. Pinned in Task 4.
- **Stale stored global.** A stored global set id the catalog lacks falls back to `classic`. Pinned in Task 4.
- **Storage blocked.** With `localStorage` throwing on read and write, the service still works for the visit. Pinned in Task 4.
- **Portrait without a face.** A set that has a portrait but no face crop gives no face, so the phone tile shows that set's portrait and never another set's face. Pinned in Tasks 3 and 5.
- **Kingdom Wars and hidden seats.** A `kingdomWars:` id uses the base General's override, and a face-down General keeps the shared card back in every set. Pinned in Tasks 3 and 5.

### Task 1: Pipeline understands art sets

**Files:**
- Modify: `scripts/assetlib/plan.py`, `scripts/assetlib/ops.py`
- Create: `scripts/assetlib/test_art_sets.py`

**Interfaces:**
- Consumes: the existing `Output`, `plan_outputs`, `_crop_outputs`, `files_under`, `marked_image` (from `test_crop.py`) and `make_layout` (from `testutil.py`).
- Produces: a recipe flag `"boxesOptional": true` on a crop recipe, and a recipe op `"art-sets"` whose key is the output path, for example `"generals/skins/art-sets.json": { "op": "art-sets", "skins": "generals/skins", "faces": "generals/faces", "registry": "generals/skins/sets.json" }`. Its output has this shape:

```json
{ "order": ["classic"],
  "sets": { "classic": { "names": { "en": "Classic", "vi": "Cổ điển" }, "provenance": "…", "portraits": ["cao-cao"], "faces": ["cao-cao"] } } }
```

- **Registry file** `assets-src/generals/skins/sets.json`: `{ "<set>": { "names": { "en", "vi" }, "provenance" } }`, in display order. Its recipe is `master-only`.
- **Coverage rules** (all `PlanError`s that name the set or file):
  - The set folders are the directories directly under the skins folder, and they must equal the registry ids.
  - Every skin master `<set>/<force>/<pinyin>.<ext>` must be a value in `skins.json`, and the index lists the General id for it.
  - `classic` must be in the registry and must have a portrait for every id in `skins.json`.
  - Face coverage comes from the planned crop outputs of the recipe named by `faces`.
- **Output sources and settings:** the sources are the registry, `skins.json` and every skin master. The index itself goes in the output's `settings` (`{'index': {...}}`), so a changed face box makes the output stale.

- Produces, all exported from `content` (`artSets.ts`):

```ts
export type ArtSetId = string;
export const DEFAULT_ART_SET: ArtSetId; // 'classic'
export interface ArtSetEntry { names: { en: string; vi: string }; provenance: string; portraits: readonly string[]; faces: readonly string[] }
export interface ArtSetCatalog { order: readonly ArtSetId[]; sets: Readonly<Record<ArtSetId, ArtSetEntry>> }
export interface ArtChoice { global: ArtSetId; overrides: Readonly<Record<string, ArtSetId>>; catalog: ArtSetCatalog }
export const ART_SET_CATALOG: ArtSetCatalog;
export const DEFAULT_ART_CHOICE: ArtChoice; // global classic, no overrides, the real catalog
export function setsCovering(baseId: string, catalog?: ArtSetCatalog): ArtSetId[]; // in catalog order
export function resolveArtSet(baseId: string, choice: ArtChoice): ArtSetId;
export function artSetName(entry: ArtSetEntry, locale: string): string; // 'vi' gives names.vi, anything else names.en
```
