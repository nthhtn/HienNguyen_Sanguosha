# Wiki Pages per Deck, with Per-Skill Status Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Separate Wiki pages for the Default and Alternate decks, a Default and an Alternate button in the nav bar, and a visible "works in the game" state on every skill and card entry.

**Architecture:** The content package computes everything the pages show (`wikiGenerals` gains a per-skill status; `wikiCards` takes a deck). The Angular pages only render it; the deck comes from route data (`/wiki/default/...` and `/wiki/alternate/...`). Alternate cards are built from `projects/content/data/decks/alternate/` and joined to Default's data by card id.

**Tech Stack:** TypeScript, Angular (standalone components, signals, Material), Jest.

**Spec:** `docs/superpowers/specs/2026-10-21-deck-wiki-design.md` (approved). It builds on the deck-choice work on branch `feat/alternate-deck-crawl`, where this plan runs.

## Global Constraints

- CLAUDE.md applies: rule/status logic lives in the content package; components only render. UI text: English Title Case for names and short labels, sentence case for status lines and empty states; Vietnamese sentence case, new text is a draft (do not touch `review.json`); both catalogs get the same keys.
- Default's Wiki content and its existing Wiki tests keep passing; only addresses, the per-skill status and the nav change there.
- The Chinese card text is content data, never an i18n catalog entry. Do not edit the deck data files or the crawler.
- Skill status is read from the game's own skill code (`GENERAL_SKILLS`), never guessed.
- Commits end with `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
