# Art sets: alternate General artwork a player can switch

## Intent

Let a player replace the portraits the game shows for Generals with an alternate set of artwork, for all Generals at once or for one General at a time.

- **Why:** The project may gain more than one set of General artwork, and players have different tastes. Today there is exactly one portrait per General and no way to change it.
- **Who:** Every player, on the desktop board, the phone board, the Rules Wiki and the online screens. Each player chooses for themselves.
- **Success:** A player picks an art set once and sees it everywhere a General portrait appears. A set that lacks some Generals still looks complete, because the missing ones show the classic portrait.

## Vocabulary

- **Art set:** A named collection of alternate artwork for Generals. The current artwork becomes the art set `classic`.
- **Skin:** Keeps its current meaning, the single portrait image of one General in one art set. The code and files already use "skin" this way (`generals/skins/`, `skins.json`, `generalSkinUrl`).
- **Card art:** Unchanged. It means the crawled full-card scans (`cardArtUrl`, `generals/cards/`). Card art is not part of an art set.
- **Face:** The square crop of a portrait the phone board shows on its small seat tiles (`generalFaceUrl`).

## Goals

1. **Several sets.** The content layer knows a registry of art sets, and `classic` is always present and always complete.
2. **Partial sets.** A set may cover only some Generals. Every lookup falls back, and a missing image is never an error and never a broken picture.
3. **Global choice.** A player picks one set as their default.
4. **Per-General override.** A player may pick a different set for a single General. It beats the global choice for that General only.
5. **Everywhere.** Every place that shows a General portrait or face follows the choice.
6. **Drop-in sets.** Adding a set is a new folder of masters, one recipe entry and one registry entry. It touches no code.

## Non-goals

- **Voices.** An art set holds portraits and their face crops only. Death voices stay keyed by the General's classic pinyin name (`audio/death/generals/<force>/<pinyin>`).
- **Card art.** The crawled card art, playing-card art and the Rules Wiki's card pictures are outside art sets.
- **Special art.** The face-down card (`hidden`), the placeholder and the Ambitionist art stay shared by every set.
- **Server sync.** The choice lives in the browser, like the battlefield background and the music setting. Syncing it to an account is a later change.
- **Other players.** The choice changes only the viewer's own screen. It is never sent to the server, and never to other players.
- **User-supplied sets.** Players cannot upload or install sets.
- **The first real set.** This work builds the mechanism. Producing the first non-classic set's artwork is a separate task.
- **Engine, server and protocol.** None of them change.

## Anti-goals (a failure even if it technically works)

- A broken or blank image appears because a set lacks a General.
- Moving `classic` changes a shipped file's bytes. The move must be byte-identical, like the 2026-11-06 restructure.
- A player's choice affects what another player sees.
- Adding a General becomes harder than today. A new General still needs only its classic portrait. Other sets are optional.
- CI needs a new tool, or `npm run assets:check` stops being the single guard that `assets/` is current.
- Game rules or engine state learn about art sets.

## Constraints

- **Layering (CLAUDE.md).** The engine, server and `protocol` do not change. The preference is presentation-layer state. The content layer resolves URLs.
- **Assets pipeline.** `assets-src/` holds masters and `assets/` is generated by `asset-recipes.json` (spec `2026-11-06-assets-src-pipeline-design.md`). References carry no extension, and `assetFile()` adds the shipped one.
- **Storage.** Browser storage can be missing or blocked, so every read and write is wrapped in try and catch, and the choice then holds only for the visit. This follows `battlefield-background.service.ts`.
- **UI text (CLAUDE.md).** English labels are Title Case for names and buttons, and sentence case for hints and status lines. Vietnamese is sentence case everywhere. New Vietnamese text starts as a draft that `npm run i18n:status` reports.
- **Kingdom Wars Generals** resolve through their base General (`baseGeneralId`). Art sets key on the base General, so one image serves both.
- **Licensing.** The existing art carries copyright limits (see the asset README). Each set's provenance goes in its registry entry, and the same rule applies: Remove or replace on request.

## Approaches considered

### Settings model

- **A. Global only.** One chosen set, with missing Generals falling back to `classic`. Simplest, but a player cannot mix sets.
- **B. Global plus per-General override (chosen).** The global set is the default, and a map `{ baseGeneralId: setId }` overrides it per General. With partial sets, mixing is the likely use ("set B, but classic for Cao Cao"). The lookup already takes a General id, so the override costs a map and a row of UI.
- **C. Per-General only.** There is no global default, so switching everything means changing every General. Rejected: It does not fit the idea of a set.

The user chose **B**. Build the global choice first inside the plan, then the override on top.

### Folder layout

- **Set-first (chosen):** `generals/skins/<set>/<force>/<pinyin>`. A new set is one folder, its coverage is visible from its folder, and `classic` is a pure move of today's files.
- **General-first:** `generals/skins/<force>/<pinyin>/<set>`. It groups all variants of one General, but adding a set touches every General's folder.

The user chose **set-first**.

### Where a set's coverage comes from (my call)

- **Generated index (chosen).** `assets:build` writes `assets/generals/skins/art-sets.json`, which lists, per set, the General ids that have a portrait and the ones that have a face. It cannot drift, because `assets:check` already fails when generated files are stale.
- **Error fallback only.** Request the set's image and fall back when the load fails. It needs no index, but it makes a visible flash and a 404 per missing General.
- **Hand-maintained list.** It drifts from the folder, and a General added to a set would silently not show.

## Design

### Folders

```
assets-src/generals/skins/skins.json               stays; values stay set-less ("wei/caocao")
assets-src/generals/skins/<set>/<force>/<pinyin>.png
assets/generals/skins/<set>/<force>/<pinyin>.webp
assets/generals/faces/<set>/<force>/<pinyin>.webp
asset-crops-faces.json                             keys become "<set>/<force>/<pinyin>"
assets/generals/skins/art-sets.json                generated coverage index
```

- **Move.** `generals/skins/{wei,shu,wu,qun}` becomes `generals/skins/classic/{wei,shu,wu,qun}`, and `generals/faces` follows. The multiset of file hashes before and after is identical, apart from the regenerated `asset-lock.json` and the generated index.
- **Recipes.** The existing `generals/skins` and `generals/faces` entries already apply to subfolders, so a new set needs no recipe line unless it wants different sizes or quality.
- **Face crops.** Each set carries its own crop boxes, because different artwork has a different face position. A set with a portrait but no crop box simply has no face, and the phone tile already falls back to the portrait (`generalFaceUrl` returns null).
- **Death voices** keep using `skins.json`, so they do not move.

### Content layer (`projects/content`)

- **Registry.** A data file lists the sets: `id`, a name per locale, and provenance. `classic` is the default (`DEFAULT_ART_SET`).
- **Lookups.** `generalSkinUrl(id, choice?)` and `generalFaceUrl(id, choice?)` take an optional resolved choice `{ global, overrides }` and return the first of these that exists:
  1. The General's override set, if the override names a set that covers it.
  2. The global set, if it covers the General.
  3. `classic`.
  4. For a portrait only: the existing card-art and placeholder fallbacks.
- **Pure.** The functions do no storage and no Angular. With no choice given, they behave exactly as today, so existing callers and tests keep passing.
- **Unknown ids.** A stored set id the registry no longer has is ignored, and the lookup moves down the chain.

### Application and presentation layers (`projects/app`)

- **Service.** An `ArtSets` service (root-provided, signals) holds `global` and `overrides`, persists them in `localStorage` (two keys), and exposes the resolved choice as one signal.
- **Call sites.** The following read that signal, and each one computes its URL from it:
  - `seat-avatar`, `seat-portrait` and `card-art` (Play screen)
  - `phone-seat-tile` and `seat-details-dialog` (phone board)
  - `scene-seat` (Rules Wiki scene)
- **Picker.** A dialog, opened from the toolbar like the Battlefield menu, with:
  - A global choice with a small preview of a few Generals per set.
  - A list of Generals, each with a choice of "Use Global Set" or any set that covers that General.
  - The toolbar entry is shown only when more than one set ships.
- **Online and phone.** Both use the same service, so there is no protocol change and no change to the duplicate local and online screens' structure.

### Pipeline and tooling

- **Build.** `scripts/assetlib` is extended to emit `art-sets.json` from the folders it already walks. It uses only the standard library plus what the image ops already use.
- **Check.** `assets:check` fails when the index is stale, with no new CI tool.
- **Skills and docs.** The `add-general` and `add-general-skill-preview` skills, `projects/content/assets-src/README.md` and `docs/architecture/content-and-extensibility.md` describe the classic path and say that other sets are optional per General.

### Tests

- **Lookups:** Override beats global, global beats classic, a missing General falls back to classic, an unknown set id is ignored, and Kingdom Wars ids use the base General.
- **Guard:** The existing test that every `/images/...` path in source points at a real file covers every set, so no set's index entry names a file that does not exist.
- **Service:** Storage missing or blocked still works, and a stale stored id falls back.
- **Pipeline:** The `classic` move is hash-identical, and a second sample set (a fixture in the pipeline's own tests) produces the right index and faces.

## Settled during review

- **Keys.** `skins.json` stays keyed by base General id and set-less, and it remains the one id-to-file map for portraits, faces and death voices. Lookups reuse `baseGeneralId`, and the generated index is keyed by base General id. A Kingdom Wars General with no base art keeps today's placeholder.
- **Index loading.** The lookups stay synchronous. The content layer imports the generated `art-sets.json` at build time, the same way it already imports `skins.json`, `sheets.json` and the preview index. These generated files are committed, so no extra ordering is needed in `verify` or the tests.
- **Face boxes.** `asset-crops-faces.json` is maintained by hand today, and no skill writes it. Its keys gain the set prefix, and the references in `docs/architecture/frontend.md` and the assets README follow. The `add-general` skill says that a General's classic portrait is required and its face box is optional.
- **Call sites.** The six listed components are the ones that call `generalSkinUrl` or `generalFaceUrl` today. Treat the list as a floor: Grep again at build time and cover any other portrait call site. Damage and chain animations are sprite sheets, not portraits, and are unaffected.
- **No cache to bump.** The app has a web manifest and no service worker, so nothing precaches portrait URLs. Moving `classic` changes URLs only, and hard-coded paths in docs and skills follow.
- **Picker reach.** The art-set entry sits in the app toolbar on every screen, the Rules Wiki included. Unlike the Battlefield menu, it is not limited to a board on screen. The phone board uses whichever menu it has today. If a screen has no menu, the builder adds the entry there.

## What is left to the builder

- **Picker layout:** Exact dialog layout, wording and the Vietnamese draft text, within the UI text rules above.
- **Index shape:** The exact JSON shape of `art-sets.json`, as long as it lists portrait and face coverage per set.
- **Loading:** Whether a set's index is read eagerly or lazily, if the file size ever matters.
- **Preview Generals:** Which Generals the picker's preview uses.

## My calls (not yet confirmed)

- **Wiki follows the choice.** The Rules Wiki's scene portraits follow the chosen set, so a player sees one look everywhere. The Wiki's card art stays unchanged.
- **Generated coverage index** rather than error fallback or a hand-kept list.
- **Picker hidden with one set.** Until a second set ships, the toolbar entry does not appear.
- **Local storage only,** with two keys (`art-set` and `art-set-overrides`).
- **Set id `classic`.** It is an art-set id, separate from the deck ids (`identity`, `kingdomWars`).
